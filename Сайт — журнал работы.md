# Сайт ivangrigorenko.com — журнал работы

Рабочий журнал проекта. Веду по ходу, чтобы при обрыве контекста ничего не терялось.
Последнее обновление: 2026-10-06.

## Что это за проект

Копия сайта-портфолио Ивана, собранная на Next.js. Оригинал сделан в **Figma Sites**
и сейчас лежит на домене `ivangrigorenko.com`. **Цель — довести копию до полноценного
сайта и перевести домен на неё.**

- Прод копии: https://ivangrigorenko-site.vercel.app
- Репозиторий: `tank-dsgn/ivangrigorenko-site` (приватный), автодеплой по push в `main`
- Оригинал: https://ivangrigorenko.com

## Стек

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind 4 · деплой Vercel.
Node лежит в `~/.local/node/bin` и не входит в PATH — перед командами:
`export PATH="$HOME/.local/node/bin:$PATH"`.

## Где брать исходные данные

**Figma MCP для этого сайта не работает.** Dev Mode MCP не читает файлы `figma.com/site/`
(проверено, Иван владелец — дело не в правах). Файл `figma.com/design/PcKsfvEhQUMve7PNQ3b6NC`
(«Site layouts») читается, но отдаёт такой же машинный вывод, архитектуру не улучшает.

**Рабочий источник** — выгрузка опубликованной страницы:

```
https://ivangrigorenko.com/_json/39c51217-69ff-4444-95d1-588378532cd6/<страница>.json
```

Английская главная лежит как `_index.json`. В выгрузке — настоящее дерево узлов Figma:
auto-layout, отступы, типографика, заливки, три брейкпоинт-фрейма (1280 / 800 / 375),
имена компонентов и переменных.

**Копии выгрузок лежат в репозитории: `tools/figma/export/*.json.gz`** (кейсы, главные,
«Обо мне»). Генератор читает их оттуда. После переключения домена оригинал на Figma Sites
исчезнет — другого источника не будет. `--fetch` перекачивает выгрузку с оригинала.

## Генератор вёрстки

`tools/figma/` переводит дерево Figma во flex-вёрстку. **Им собраны все страницы
с содержимым: 12 кейсов, обе главные, обе «Обо мне».** Руками написаны только
шапка, футер и экран меню (`Header`, `Footer`, `MenuPage`).

```bash
node tools/figma/generate.mjs pot-ru --sections          # одна страница
node tools/figma/generate.mjs index --sections --out components/generated/home-en
node tools/figma/fonts.mjs                               # шрифты макетов → public/fonts, app/figma-fonts.css
tools/verify/regen.sh                                    # всё сразу + сборка + сервер на :3000
```

| Файл | Что делает |
|---|---|
| `resolve.mjs` | Собирает дерево страницы и **разворачивает инстансы компонентов** |
| `nodes.mjs` | Figma → CSS: размеры, привязки, заливки, обводки, типографика |
| `emit.mjs` | Дерево → JSX: картинки, текст, ссылки, состояния, поведение |
| `generate.mjs` | Режет страницу по секциям в `components/generated/<страница>/` |
| `fonts.mjs` | Скачивает шрифты макетов и пишет `@font-face` |
| `overrides.json` | Одна таблица: подпись карточки «Смотрите также» → проект |

### Что лежит в выгрузке и как это читать

Раньше считал, что переопределения инстансов в выгрузке не применяются, и держал
ручные таблицы правок. Это было неверно: всё есть в данных, нужно применить самим.

- `instance.overrides = [{ key, value }]` — `key` это путь из имён слоёв с номером
  среди одноимённых соседей (`["Frame0","Levels0","Wifi0"]`), `value` — новые свойства:
  `characters`, `fills`, `size`, `visible`, `interactions`, `style`; для вложенного
  инстанса — `mainComponentId` и свой `overrides` (он **дополняет** список вложенного
  инстанса, а не заменяет его).
- `instance.componentProperties` + `node.componentPropertyReferences` — свойства
  компонента: текст, видимость, подмена вложенного компонента.
- `instance.uniformScaleFactor` — масштаб. Дети мастера умножаются на него.
- `node.overrideKey` — у библиотечных компонентов дети адресуются по нему, не по id.
- `stablePathToAssetInfo["I<инстанс>;<вложенный>;<узел>"]` — своя картинка узла в
  конкретном инстансе.
- `assets[hash].offsets` — на сколько картинка выступает за коробку узла (тень,
  обводка): в процентах, у линий нулевой толщины — в пикселях.
- `fonts["Семейство:Начертание"]` — файл шрифта, вес (SF Pro Semibold = 590), оси.
- Нет `primaryAxisSizingMode` / `counterAxisSizingMode` = блок **обнимает содержимое**,
  `FIXED` = размер задан. Высоту ставим только там, где `FIXED`.
- `targetAspectRatio` — пропорции зафиксированы: тянется по одной оси, вторая считается.
- Текст: `\n` — абзац, `U+2028` — перенос строки, `lineTypes` — списки,
  `characterStyleOverrides` + `styleOverrideTable` — стиль части текста,
  `textTruncation: ENDING` — обрезка с многоточием, `lineHeightUnit: INTRINSIC_%` —
  высота строки из шрифта.
- `behaviors`: `scrollParallax` (параллакс обложек), `code` (Lightbox — увеличение по
  клику). `appear` в видимых деревьях не встречается.
- `interactions`: `ON_CLICK`/`ON_HOVER` → `SWAP_STATE` — смена варианта компонента
  (карусель, тумблер темы, наведение на кнопку); `NAVIGATE`/`URL` — ссылки.

## Как проверять точность

Сверка автоматическая: Chrome без окна снимает оригинал и копию, скрипт сравнивает
высоту страницы, положение каждой картинки и каждого текста, кегль, вес, шрифт и цвет.
**Высота страницы сама по себе ничего не доказывает** — она совпадала и при сломанной вёрстке.

```bash
tools/verify/regen.sh                         # перегенерировать, собрать, поднять :3000
tools/verify/matrix.sh 1440                   # все кейсы на ширине 1440
tools/verify/matrix.sh 375 home-ru index      # отдельные страницы (index — английская главная)
tools/verify/report.sh 1440 pot-ru            # что именно расходится
node tools/verify/path.mjs pot-ru 1280 "^Вход в прил" 6   # путь до узла в дереве
node tools/verify/near.mjs pot-ru 1440 6800 7000          # что стоит в полосе страницы
node tools/verify/behaviors.mjs pot-ru 1280               # где параллакс и увеличение
```

Команды с сетью и Chrome запускать без песочницы. `COPY_ORIGIN=https://…vercel.app`
сверяет выложенный сайт.

⚠️ **Не опрашивать прод в цикле без пауз.** 04.10 я ждал деплой циклом `until curl …`,
защита Vercel начала отдавать автоматическим запросам проверочную страницу (403),
цикл не завершился и приложение закрылось. Ждать деплой — редкими запросами с паузой.

В отчёте остаются только различия разметки, а не вида: в шапке и футере текст измеряется
вместе с полями ссылки, бургер и крестик — встроенный svg.

### Качество картинок (06.10)

Иван: «почти у всех экранов плохое качество». Причина — при первой выгрузке картинки
были скачаны уменьшенными, до 1600px по длинной стороне: файл 721×1600 показывался на
месте шириной 914px. Оригиналы на Figma Sites в 2–2,5 раза крупнее.
`python3 tools/figma/refetch_assets.py` перекачал оригиналы: заменена 91 картинка из 259,
потолок 3000px по длинной стороне, WebP q88. `public/a` 32 → 42 МБ. Теперь у растровых
картинок на Eazychange файл не меньше 1.3× от места показа (кроме двух мелких экранов —
там оригинал сам небольшой). Касается всех страниц, не только Eazychange.

### Наведение как в оригинале (05.10, по видео Ивана)

Иван записал экран с голосом: на оригинале карточки «Смотрите также» и карточки
проектов на главной при наведении **плавно** приподнимаются, картинка плавно растёт.
У меня состояния просто сменяли друг друга слоями.

Сделано в генераторе (`hoverMorph` в `emit.mjs`): если состояние «наведение» отличается
от обычного только положением, размером и краской, выводится одно состояние, а разница
уходит в правила `:hover` с переходом из макета (300 мс, `cubic-bezier(0, 0, 0.58, 1)`):
`translate`, `scale`, `box-shadow`, `color`. Правила лежат в `<style>` в начале секции.
Проверено мышью: карточка на главной −6px, картинка 800×400 → 854×427; «Смотрите также» —
−6px, картинка 566×283 → 622×311, подпись индиго. Числа совпадают с макетом.
Карусели и тумблер темы по-прежнему на `VariantGroup` (смена слоёв).

Доработки 06.10 (правила — `hover` в `tools/figma/overrides.json`):
- **Карточка Ostral в «Смотрите также»** вела себя иначе: в макете её состояние «наведение»
  собрано по-другому (в нём осталась картинка Eazychange и лишний слой), плавно переехать
  в него нельзя. Теперь совпавшие части двигаются как в макете, а картинка обычного
  состояния увеличивается из центра в 1.1 раза (`repair.imageScale`).
- **Подпись карточки «Смотрите также» при наведении становится жирной** — просьба Ивана,
  в оригинале она только меняет цвет (`text.fontWeight: 700`).

- **Карусели едут, а не подменяются** (06.10, просьба Ивана про Eazychange). `stateMorph`
  в `emit.mjs`: если состояния блока по клику отличаются только положением частей, краской
  и содержимым отдельных листьев, выводится одно дерево, состояние хранится в атрибуте
  `data-state` на корне, разницу задают правила CSS с переходом из макета. У стрелки в
  `data-swap-map` записано, куда она ведёт из каждого состояния. Атрибут переключает
  `components/StateGroups.tsx`. Так работают: «Другие экраны» в Eazychange (лента
  −1453 / −2906px за 300 мс), карусели POT и VV, где состояния устроены одинаково.
  Где состояния устроены по-разному (светлая/тёмная тема POT: в одном картинки, в другом
  живые слои) — по-прежнему смена слоёв через `VariantGroup`.
  Проверка: `node tools/verify/ev.mjs http://localhost:3000/pot-ru 1440 tools/verify/clicks.js`.

Как разбирать видео: `~/.local/whisper-venv/bin/python` + скрипт (PyAV режет кадры,
faster-whisper расшифровывает русский). Файл из временной папки записи экрана macOS
не читается — просить положить `.mov` в папку проекта (`*.mov` в `.gitignore`).

⚠️ Сверка идёт долго: 7 страниц ≈ 4 минуты. Запускать порциями по 3–5 страниц, иначе
команда не укладывается в лимит, а вместе с ней гибнет локальный сервер на :3000.
